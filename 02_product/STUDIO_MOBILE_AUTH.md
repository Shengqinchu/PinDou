# 手机与电脑的登录入口

> 2026-09-09 新进展：账号入口现按店主要求改为注册／登录／微信登录，默认密码，验证码仅用于找回。已核实存在另一自有小程序“双吉拼豆图纸定制”的有效 API 配置，但发布状态未确认；下文旧结论“没有店主自有小程序”不再作为当前事实。共享小程序品牌可配置项和完整原生页面的边界见 [最新验证](../07_ops/STUDIO_AUTH_TABS_VERIFICATION.md)。

来源：店主2026-09-08 Toronto指出“手机用户总不能自己扫自己”，并要求直接代操作Authing控制台。以下是本轮核实的边界与接入设计，不能把未完成项标为已上线。

## 已核实

| 使用环境 | 合适的登录方式 | 本项目状态 |
|---|---|---|
| 电脑网页 | 邮箱；Authing“小登录”二维码，由手机扫码 | V6本人iPhone扫描电脑二维码、授权、绑定原邮箱、微信再次登录及工具自动登录均实测成功；权限及服务器时钟问题已修复 |
| 微信内打开手机网页 | 微信网页授权可在同一手机内完成；邮箱可用 | Authing的官方接入需要微信服务号、凭据及授权域名设置；店主目前未提供这套配置 |
| Safari／Chrome等手机浏览器 | 邮箱验证码；短信通道接通后增加短信 | 邮箱已上线；Firebase／Descope仍未完成生产适配及送达测试 |
| 自己开发的原生App | 微信移动端SDK／App拉起小程序 | 本项目是网页；控制台这个“微信移动端”选项不能当作手机网页方案 |

依据：[PC小登录](https://docs.authing.cn/v2/guides/connections/social/wechat-miniprogram-qrconnect/)、[微信网页授权](https://docs.authing.cn/v2/guides/connections/social/wechat-mp/)、[微信移动端的原生App范围](https://docs.authing.cn/v2/guides/connections/social/wechat-mobile/)、[App拉起小程序](https://docs.authing.cn/v2/guides/wechat-ecosystem/wechat-miniprogram-applaunch.html)。

没有找到当前Authing托管“小登录”明确向普通手机网页提供可直接使用的一键拉起能力的官方依据；不能凭“移动端可见”开关或二维码截图认定已经具备。服务号直连路径与以后可能采用的第三方托管手机路径需要分别核验。微信手机浏览器不必等同原生App。

## 页面接入约定

- 保留不登录浏览／选时段，只在提交预约时要求登录。
- 电脑二维码入口在真实身份源与网站回调可用后开放。
- 手机首屏使用同机可完成的登录方式，不将扫码作为必经步骤。当前可用入口为邮箱；短信完成供应商配置、额度控制和真实送达测试后加入。
- 未验证“小程序码长按识别”或“保存截图再从相册扫一扫”的跨系统行为，不以此作为手机主流程或宣称手机微信登录已适配。
- 以后具备微信内网页授权或托管手机跳转能力时，再按实际环境展示对应按钮；同一内部账号的绑定需验证，不能按昵称自动合并。
- 跳去邮箱／微信后返回，已选预约时段及表单继续保留；iOS/Android普通浏览器和微信内浏览器分别验收。

## 本轮浏览器连接检查

最初错误地使用独立Chrome通道检查，`browser_list_tabs`返回0个已连接标签；`browser_attach(autoConnect=true)`报告没有DevToolsActivePort。这些结果不能判断Codex内置浏览器是否能操作。店主明确指出目标是右侧内置浏览器，已停止要求其配置Chrome。

正确原因：Codex的in_app_browser与browser_use开关已开启，但当前版本的browser-service.mjs缓存缺失。已从同版本Codex官方安装包恢复33个原始运行文件，逐个SHA-256核验；重置初始化失败的Node REPL后，通过原生CUA接口找到并操作了店主的那个Authing标签。没有重新登录、切换外部Chrome、改动权限开关或修改运行库源码。修复细节见 `../07_ops/STUDIO_BROWSER_RUNTIME_REPAIR.md`。

已完成：显示名设为微信登录，创建pindou-wechat身份源，关联pindoupuppy应用，启用该扫码连接并把此Authing应用的默认登录方式设为扫码登录。V6正式网站入口、回调和账户桥接已上线；手机网站按实际UA保留邮箱入口，避免同屏扫码。首次使用需验证原邮箱以保留既有账户资产。

V6再次检索Authing官方文档及wxAuth发布者文档：二者的托管小程序均明确提供扫码流程，未找到可直接集成、免自有资质的手机网页一键拉起凭证或接口。微信内同机授权的已确认路线仍是服务号网页OAuth。普通手机浏览器若采用小程序URL Link／开放标签，必须取得小程序提供方支持本次登录会话的合法跳转链接，不能从一张二维码推断或拼造。当前没有这项托管接口，也没有店主自有小程序；尚未完成手机微信免扫码登录。

另外读取费用管理：当前为B2C免费版，活跃用户0/8,000，有效期无限期，支付方式为空。未开通付费版本。控制台可配置和能够生成二维码仍不等于已通过真实扫码授权、手机同屏授权或网站登录验收。
