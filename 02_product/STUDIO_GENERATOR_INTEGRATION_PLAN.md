# 生成器融入主站：实施计划与基线

日期：2026-09-09。状态：**现状审查和改造前测试已完成；功能整合待进入实施。**

用户要求：“生成器目前还是跳转过去的，我希望封装进去，并且做UI、颜色与设计上的适配……好好测试和梳理计划一下再开始。”补充确认：**完整中英双语**，覆盖上传、编辑、导出、教程等全部工具文字。

## 1. 目标体验

从主站顶部进入“拼豆图纸生成器”，继续使用主站的小狗品牌、导航、English／中文、账号入口和交互风格。工具拥有制作、我的作品、使用教程三个内部入口。主站与工具之间使用站内路由，切换时保持正在选择的照片、生成配置和编辑状态。

工作区使用白底、黑灰正文、少量浅蓝选中状态，沿用主站字体、按钮、信息提示和弹层。编辑图纸时使用紧凑顶栏、完整画布和工具面板，页脚退出工作区视野；手机以画布和主要触控工具为优先，详细选项放在可收起面板中。

顶部保留一个账号入口。工具额度紧靠生成操作，清楚标为AI积分／普通生成权益。店铺的储值分钟、到店积分和图纸工具的AI积分继续各自记账；同一账号不代表不同余额可以互相抵扣。当前费率、资格、扣费和CDK规则继续由原后端负责。

## 4. 技术方案

### 一个主站容器，按需加载工具模块

采用主站Vue Router下的工作区路由。把经核验的生成器组件、状态与API整理成可复用模块，由主站按需加载；登录、语言、品牌、弹层和全局导航由主站提供。画布绘制和制图算法继续复用当前实现。浏览器内只有一套活动的Router、Vue运行时与Pinia实例。

建议落点为独立的 `05_generator` 工作区模块，避免把整套旧App和全局样式直接导入主站。该目录只作为新的模块边界，迁移时记录来源SHA与等价性；已有 `05_web` 保留为已发布版本的兼容／回滚来源，不再形成两套长期并行维护的工具实现。模块导出路由组件、状态以及宿主接口，不自行`createApp`、`createRouter`或注册重复全局监听。

主站接入所需变更：`05_studio/src/main.ts`、`App.vue`、路由加载、账号返回地址、Vite依赖去重及发布路由。Vue、Router、Pinia按现有兼容版本锁定；本次不捆绑框架大版本升级。

| 新入口 | 功能 | 旧入口兼容 |
|---|---|---|
| `/tools` | 选图与生成配置 | `/upload` |
| `/tools/loading` | 当前任务进度 | `/loading` |
| `/tools/result/:id` | 图纸结果 | `/result/:id` |
| `/tools/editor/:id` | 图纸编辑 | `/editor/:id` |
| `/tools/works` | 当前账号／设备作品 | `/works`、`/me` |
| `/tools/tutorial` | 使用教程 | `/tutorial` |

保留旧链接参数和片段；刷新／收藏／前进后退均由同一入口恢复。更新微信及邮箱登录安全返回白名单，防止旧`/upload`回退截断新路径。私人作品、结果、编辑和生成状态页设置noindex；接口继续验证作品归属。

建议不用iframe作为最终承载：原编辑器需要协调浏览器历史、全屏尺寸、双指操作、原生下载／分享、弹层焦点和登录回跳。基于既有Vue组件完成原生整合，更容易分别验证这些行为。此选择是基于本项目代码结构的工程判断。

官方依据：[Vue Router嵌套路由](https://router.vuejs.org/guide/essentials/nested-routes.html)、[Vue组件CSS作用域](https://vuejs.org/api/sfc-css-features.html)、[Pinia组件外使用与实例注入](https://pinia.vuejs.org/core-concepts/outside-component-usage.html)。

### 状态与身份

- 主站账号作为唯一登录入口；保留现有共享用户ID、微信绑定、昵称和头像。工具调用宿主登录，不另建登录表单。
- 上传草稿、当前生成任务、配置、结果分别存储。普通站内导航恢复照片与参数；编辑内容保存状态明确可见。整页OAuth往返需要短期的本机草稿恢复方案，按账号／设备隔离并在完成／退出时清理，不把图片编码进URL或日志。
- 任务提交加单次提交锁，轮询与页面导航解耦。过期账号请求、已离开的页面和旧任务结果不能覆盖新账号／新任务或触发跳页。
- 自动保存与手动保存、下载前保存的串行关系保留；编辑期间离开时等待保存或明确提醒。网络失败保留编辑内容，并提供可恢复重试。

### 视觉与双语

- 界面背景、边框、按钮、阴影、字体和反馈色使用主站设计变量。**真实照片、画布颜色、MARD色号、网格坐标和导出像素不应用主题滤镜、换色或缩放伪装。**
- 上传区作为视觉主体；桌面选项集中在侧栏，手机先选图再设置；主要生成按钮附近显示所选尺寸与实际额度消耗。
- 小标题可用现有手写体；色号、坐标、数字、输入框使用清晰正文／等宽字体。彩色只用于内容和必要状态，不把所有控制都变成彩色卡片。
- 所有工具文案进入模块化中英字典：按钮、状态、校验、日期数量、空状态、动态任务错误、快捷键说明、辅助名称及下载提示。语言切换不能清空照片或撤销栈。
- `message_cn`等后端字段按错误码／任务阶段映射双语；未知错误使用可定位的双语通用提示。接口参数、色号和身份标识保持机器值。
- 重新采集适配后的中英教程截图，避免英文页面展示整张中文旧界面图。图片alt、说明与实际功能一并验证。

## 5. 实施顺序与每阶段出口

| 阶段 | 实际工作 | 进入下一阶段前的验收 |
|---|---|---|
| 0 已完成 | 冻结线上构建／源码、页面清单、独立测试环境、记录现存问题 | 基线可复跑，当前版本及数据边界明确 |

| 2 视觉样板 | 先实现上传页和编辑器，桌面／手机两种布局，统一控件和信息层级 | 实际可操作截图、320窄屏／短屏／200%缩放、画布触控与弹层通过，再推广到其他页面 |
| 3 完整工具与双语 | 生成中、结果、作品、教程、额度／CDK、全部错误及空状态；更新教程截图 | 中英文逐页完成，无遗留中文按钮／提示、无字号撑破或布局跳动；动态错误同样双语 |
| 4 回归与恢复 | 全流程、慢网、失败重试、多窗口、撤销保存、退出／换账号、下载与设备权限 | 单任务无重复提交／扣费，作品与余额隔离，输出结构与旧基线一致 |
| 5 发布 | 可回滚构建；先隔离预览，再更新站点入口与资源缓存 | 公网资源／路由／版本、原账号／作品／余额／管理员内容逐项核对；旧链接继续可用 |

每阶段把实现、截图、失败项和修复结果落档。避免在一个未经验证的总改动里同时替换路由、字体、画布交互、翻译和计费状态。

性能按当前构建记录对照：主站首次加载不拉取整套画布和全部色卡；进入工具按需加载，常规编辑反馈不因全站主题重渲染而变慢。实际任务时延受AI服务影响，界面动效不能伪装任务已完成。
