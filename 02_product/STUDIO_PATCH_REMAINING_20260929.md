# 布贴赠送剩余名额独立调整

来源：店主截图 `codex-clipboard-8a4ebc36-a61f-4ff1-b6dc-0ae7bac4f92c.jpg`，要求“加一个 可以修改剩余名额的”；明确确认“总名额不变，单独调整剩余数”。

## 行为与数据

- 预约管理 → 布贴试营业赠送名额中增加“剩余赠送名额（人数）”。例如总名额 10，剩余可单独保存为 6，顾客端展示 6/10。复用原数字输入框、抽屉、按钮与中英文字体。
- 总名额、活动起始时间、已获赠人数及赠送历史不随剩余调整而改写。可填 0–100000 的整数；空值、负数、小数不保存。
- 采用独立调整量：`remaining = max(0, quota - active_claim_guests + remaining_adjustment)`；显式调整为 N 时，`remaining_adjustment = N - quota + active_claim_guests`。
- 新预约按人数扣减，取消／删除返还，恢复预约重新检查余数；完成到店的赠送保留。最后只剩 1 个名额时，整组全部获赠，保持原超额后的返还计算。不给以前未获赠的预约补发。
- 老客户端只发送总名额／活动开关时，保持已有调整量；总名额改变仍按原规则影响可用人数。新表单仅在实际编辑剩余字段后提交该字段，避免开关或总数保存意外清掉最后一组的超额占用。
- 配置与预约占用／释放共用 SQLite 写事务和递增版本。编辑期间发生占用／释放，旧版本保存返回冲突，保留输入并提供重新加载。
- 记录调整前后值及请求内容。成功但响应丢失后的相同请求重试返回当前状态，不会再修改余数，不会把重试期间新预约占用的名额补回。
- 数据迁移仅新增 `remaining_adjustment INTEGER NOT NULL DEFAULT 0`，保留原活动、赠送记录和事件。新字段不在公开接口暴露。
- 移除抽屉标题的均衡换行，修正手机上“布”字单独占一行；标题字体、字号和交互动效保留。

## 回退注意

新增列与旧代码结构兼容，但旧后端不读取调整量。店主首次手动调整后，不能直接退回旧后端并声称余数不变；优先保留新后端只回退网站，或前向修复。不得用旧数据库覆盖新增预约／赠送记录。
