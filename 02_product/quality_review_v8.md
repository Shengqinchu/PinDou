## 议题 2 — 虎皮椒支付【最终决策：不采用】

> **用户 2026-05-26 确认**：不接入虎皮椒。MVP 期继续使用加客服扫码；PMF 后直接升级个体工商户并接官方微信支付。

最终决策：
- MVP 期：保留当前"加客服扫码付"方案，减少支付链路研发和回调风险。
- 不接虎皮椒 H5 跳转：体验割裂，用户离开小程序后断点率高。
- 不接虎皮椒支付码方案：虽然比 H5 顺滑，但仍需要第三方回调、风控与状态同步，且 PMF 后会被官方微信支付替代。

## 原始评估留存（供回顾决策思路）

**用户曾问**："不需要加客服，直接用虎皮椒"

**Claude Code PM 反对理由（针对 H5 跳转方案）**：

### 三方案完整对比
| 方案 | 工作量 | 用户体验 | 适用阶段 |
|------|--------|---------|---------|
| A. 加客服扫码（当前） | 客服 24/7 守 | 加好友 + 转账，清晰 | MVP 月入 0-1500 |
| B. 虎皮椒 + H5 跳转 | 大（独立域名 + 备案 + H5 站 + webhook） | 跳出小程序再跳回，断点率高 | 不推荐 |
| C. 个体工商户 + 微信支付 | 中等（一次性接入） | 最佳（小程序内原生） | PMF 月入 ≥ 1500 |

### B 不采用的核心理由
- 小程序内 `wx.requestPayment` 强制官方商户号 → 虎皮椒只能走 H5 跳转
- H5 跳转 = 用户离开小程序 → 付完手动回来 → 转化断点
- 工作量大（独立域名 + 备案 + H5 + webhook）但收益不如 C 干净
- 1 年内 PMF 后必被 C 取代 → 直接的技术债

### 决策树
```
现在月入 0-1500 → 保持 A（加客服扫码）
   ↓
月入达 1500（约 PMF 早期）
   ↓
直接跳 C（升级个体工商户 + 微信支付）
   ↓ 完全跳过 B
```

## 议题 4 — 色号字符颜色规律

**公式**：WCAG 简化版亮度对比度
```python
luminance = 0.299 * R + 0.587 * G + 0.114 * B  # 范围 0-255
font_color = "black" if luminance > 128 else "white"
```

**为什么 G 权重最大（0.587）**：人眼视锥细胞对绿色波长（555nm）响应最强。

**为什么只用黑白**：黑白对比度极限 21:1（WCAG 标准），任何彩色字会牺牲对比度。工业拼豆图纸行业标准。
