# 预约时间与人数修改

来源：店主 2026-10-02 批注截图 `codex-clipboard-f173b767-02f1-405d-86fa-43f5184cc9bb.png` 与两次答复。

## 需求与验收

| 项目 | 要求 |
| --- | --- |
| 管理员 | 待确认、已确认、已完成、已取消预约均可更改日期、开始/结束时间和人数；单改安排保留状态，明确选择的新状态仍按既有规则处理 |
| 顾客 | 只可修改本人未删除的预约，四种状态均有入口；修改已确认、已取消、已完成后恢复待确认 |
| 通知 | 顾客提交实际修改后向店主现有通道追加一次通知；保留新旧安排，旧未发送的安排提醒作废；通知与预约事务一致 |
| 时间与容量 | 当前营业时间与两周窗口为新待确认请求的准则，排除预约自身占位；布贴固定一小时、同一时段一组；管理员历史更正不套用后来修改的营业规则 |
| 身份与数据 | 体验类型、原创建来源及账户归属不改；没有凭联系号认领资产。原结算和积分留存，再次完成同一预约不重复赠分 |
| 历史 | 追加修改前后状态、安排及实际到店信息；顾客将已完成预约重开时，新请求的实际游玩字段清空，旧记录保存在不可改写历史和原结算中 |
| 并发和重试 | 版本冲突阻止覆盖；相同修改请求重试不重复变更、扣名额或发消息 |
| 赠送 | 原已领取赠品保留；尚未领取且已具资格的组别按修改后人数计占用；修改不会补发原未获资格的历史预约 |
| 界面 | 网站管理员抽屉、顾客预约详情及微信原生两端同时适配；复用现有字体、浅色、圆角、按钮和日历，手机触控和英文换行检查 |

## 实施顺序

1. 服务端事务、只读日历、修改审计与通知作废/追加。
2. 管理员和顾客网站表单、原生表单及缓存同步。
3. 四状态、越权、重复请求、并发占位、原资产、赠送及通知的隔离测试。
4. 文案、构建与手机/桌面中英文交互验收。
5. 按当前线上清单打包网站和明确的服务变更，保全双库与旧生成器，刷新公网核验；原生包验收和平台状态分别记录。

## 本地验证

- 203 项预约/通知回归、36 项钱包/赠送/通知检查通过；新增改约、手机发送桥、微信订阅任务及 Telegram 的 41 项检查通过。包含同一布贴时段的并发修改只能成功一组、管理员历史更正不改原结算、同一预约重开后不重复赠分。
- 网站类型/文案/构建、原生 H5 与微信构建通过。85 个文案模块；原生 26 页面、213 文件、1,033,108 字节，旧生成器路由/资源/API 标记均为零。
- Chromium/WebKit，中英文，320/390/768/1440px 的网站及原生 H5 共 12 组操作检查通过，包含两端丢失响应后的原请求重试。目视核对了中文窄屏弹窗和原生弹窗；模板人数、白色面板、圆角和固定提交操作已修正。
- 所有可写操作使用 loopback 服务、独立临时库和虚拟身份，通知发送使用替身；没有创建生产测试用户或预约。H5 模拟与原生构建不等于真机交互或正式上架。
- 发布包以已核验的线上 `20260930162351-studio-v7` 为基准。服务默认文案只更新 `reservation-edit`、`owner-notifications`、`owner-wechat` 和 `messaging` 本次字段，其他线上默认值保持；原生日记默认文件等不随通用生成器输出替换。
