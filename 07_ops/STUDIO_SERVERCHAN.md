# Server 酱店主预约提醒

授权来源：2026-09-10 店主要求先接入 Server 酱，调试阶段使用本人微信，之后换到女朋友的微信。

## 行为

- 新预约提交成功：发送「新预约待确认」。顾客自行取消成功：发送「顾客取消预约」。店主自己确认／取消／改备注不额外通知自己。
- 通知只包含称呼、日期、起止时间、人数、预约编号和后台入口；不向第三方发送联系方式、顾客留言或店主私密备注。
- `owner_notifications.py` 在预约事务中追加唯一事件，在独立 worker 中发送。预约的网络响应不等待 Server 酱。
- 每 3 秒处理一条，失败按 1 分钟、5 分钟、15 分钟等间隔退避，最多 8 次；任务与请求计数持久化，进程重启后可以恢复。发送租约 90 秒，外部请求超时 12 秒。
- 预约已确认／取消／删除时，不再发送过时的「新预约待确认」。任务超过 24 小时停止发送。未启用时产生的事件留有未发送记录，启用后不补发历史提醒。
- 用户重复提交预约或取消请求不会新增相同通知。外部服务没有业务幂等键，若服务已接受、进程却在保存结果前中断，恢复时仍有极小的重复可能；不宣称跨服务 exactly-once。

## 配置与维护

店主工作台顶部「微信提醒」打开设置抽屉：填写 SCT 开头的 **Turbo** SendKey，开启提醒，保存后发测试。不能填写 Server 酱³ 的 sctp 密钥。

- 接收微信需在 Server 酱「通道配置」中启用方糖服务号等实际可用的微信通道。
- SendKey 存于生产 `/opt/pindou/studio/shared/serverchan-secret.json`，0600 权限，pindou 用户持有；不放进数据库、静态资源、API 响应、发送记录或 Git。可用 `STUDIO_SERVERCHAN_SENDKEY` 提供初始值，私密文件优先。
- 页面只返回配置状态和不可逆短指纹。保存后清空密码输入框，关闭抽屉也清空未保存的密钥。
- 换接收人时，用对方微信登录 Server 酱，获取其 SendKey，再在此处覆盖保存，后续请求使用新的接收渠道。确认测试收到后，可在原 Server 酱账号撤销不用的旧密钥。
- 配额默认最近 24 小时 5 次，可选择已开通会员的 1,000 次。这是网站保护阈值，不会购买会员；滚动窗口不依赖平台时区，失败和测试都计入。
- 测试每小时最多创建 3 条，按钮具备幂等重试；无需创建真实顾客预约。
- 发送记录区分排队、发送中、等待重试、服务已接收、失败、未发送、过期。`服务已接收`仅代表提供商 API 接受；实际微信到达需要接收者确认。
- HTTP POST 仅发送到固定 `https://sctapi.ftqq.com/`，拒绝重定向，错误文本按固定分类记录，避免包含密钥的请求 URL 泄露。

## 接口

全部要求完整店主权限：

- GET/PUT `/studio-api/manage/owner-notifications`：状态、配置、最近 30 条记录。
- POST `/studio-api/manage/owner-notifications/test`：UUID 请求编号，一条测试消息。
- POST `/studio-api/manage/owner-notifications/{id}/retry`：仍有效的失败任务重试，不重复发送已接受的任务。

数据库新增 `studio_owner_notification_settings`、`studio_owner_notifications`、`studio_owner_notification_attempts`。不迁移历史预约或账户资产。
