# 布贴 DIY 预约验收（2026-09-28）

用户以三张标注截图要求添加布贴预约，特别强调与原网站的设计和按钮 CSS 一致。[需求与解释](../02_product/STUDIO_PATCH_BOOKING_20260928.md)。

## 实现与数据边界

- 三种体验和一个合并优惠，共四个模块；布贴不显示价格。旧优惠继续读取原文案模块及店主发布的覆盖值。
- `booking.plan=patch` 使用既有预约 JSON，不迁移预约表。布贴一分钟不多不少地按 60 分钟预约，待确认立即占用独立的一组容量；拼豆人数／组数、至少两小时、满员缓冲规则保留。
- 所有占位与重开检查在 SQLite `BEGIN IMMEDIATE` 内。取消和删除释放，恢复或重新确认冲突时拒绝。管理员可代建、确认、完成、删除、恢复，时段表标注体验及状态。
- 完成布贴记录的经营类别是布贴，金额待填写，不套用拼豆单价。现有预约积分来源规则保留，管理员录入不赠预约积分；不自动扣储值时长。
- 新卡片复用原卡片交互；筛选按钮使用既有 `desk-button secondary`。中文标题、正文、英文字体保持，字体子集只扩充新增字形。通知识别布贴，顾客提醒继续纯英文。
- 生产只做只读验收，不建立测试预约、不发送测试短信或邮件。原生小程序包本轮未发布；旧拼豆 API 缺省参数保持兼容。

## 本地验证

环境：隔离工作树 `codex/studio-patch-booking-20260928`，基线 `ef99fda`；原工作区未提交功能不进入此包。QA 服务只监听回环、临时数据库、无通知消费者。

- 后端专项及相邻模块：140 项通过。布贴专项 29 项，包括并发争抢、幂等、一小时及闭店边界、交错半小时重叠、取消／删除／恢复、两种容量隔离、管理筛选、财务和英文通知。
- 全量首次执行：567 通过、2 失败。新增测试错误地依赖两个同时间戳预约的列表顺序，已改为按预约 ID 查找并重跑 29 项通过。另一个是旧的 `test_custom_names_are_not_rewritten`：期待“拼豆用户”原样保留，但基线 `customer_auth.display_name` 已明确给此默认占位名追加唯一后缀。提取 `ef99fda` 的函数与默认文案独立复现；相关业务代码和旧测试均未在本次改动。
- Chromium / WebKit × 桌面／手机 × 中英文：4 组实际顾客提交 → 后台筛选／确认 → 取消释放通过，无页面异常。WebKit 为浏览器引擎模拟，未冒充 iPhone / 微信真机收件验证。
- 另 3 组样式与选择回归：1440、320、390 宽；字体／字重／颜色／圆角与原卡片一致；实际按住为 `scale(.975)`、下移 1px；键盘聚焦、下一步禁用和访客选择减少动态效果均正常；按时仍选两小时、全天仍至闭店、布贴固定一小时。
- Vue 类型、83 模块文案契约、Vite build、`git diff --check` 通过。新的一小时后台色块显示类型、状态、姓名、人数和时间。
- 截图与原始结果保存在工作树忽略目录 `artifacts/patch-booking/`，包括 `browser/results.json`、`browser/style-results.json`、`patch-tests.log`、`baseline-nickname.json`、发布前指纹。仅包含本地虚构 QA 预约。
