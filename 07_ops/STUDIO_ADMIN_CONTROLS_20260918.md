# 2026-09-18 后台删除、积分抵扣和撤销验收

来源：店主四张后台截图；随后明确“保留历史记录，移除顾客账户”。本轮以当前业务分支 `1d0d8b6` 和新服务器实际运行的 `20260917020325-studio-v7` 为基线，在独立 worktree 实现。原工作区的生成器、通知和其他未提交修改没有进入候选。

## 行为

- 小店增加单个及批量删除，可从“已删除商品”恢复。删除阻止新订单与旧购物车继续下单；商品、来源、订单快照与库存保留，已有订单仍可正常履约，种子初始化不会重新展示删除商品。
- 顾客账户从正常列表移除，可从“已删除账户”恢复。历史预约、稳定登录身份、余额及所有流水保留；登录不会自动恢复列表记录或重复赠送积分。本轮不注销共享微信/网站登录。
- 后台可按 CAD 0.01 抵扣或使用全部积分，332 积分等于 CAD 3.32；用整数积分及整数分校验账单和余额，无浮点乘法扣分。原顾客整数 CAD 提示与 `redeemable_cad` 向下取整不变，优惠互斥与记账说明仍需确认。
- 撤销按钮原先在明细上方打开表单，用户仍停在原滚动位置。本轮直接滚动并聚焦撤销表单，错误在当前表单内显示，完成后定位成功反馈；撤销仍追加反向流水，保留原记录与幂等保护。

## 数据与请求保护

新增 `studio_archives` 和 `studio_archive_actions` 两张表，不删除业务记录。删除/恢复在一个 SQLite 事务内校验全部版本、修改列表状态和写审计；同一请求可以安全重试，旧删除请求在恢复后重试也不会再次删除。账本触发器、来源资格、余额限制和既有 idempotency key 规则保留。

本轮服务端行为变化仅 `admin_archives.py`、`commerce.py`、`shop_catalog.py`、`wallet.py` 和 `content-defaults.json`（只追加 `admin-controls` 模块）。其他发布服务文件逐一与生产当前文件核对，复用原始字节；不更换生成器或通知服务代码。
