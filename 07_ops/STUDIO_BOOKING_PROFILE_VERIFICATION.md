# 预约资料保存与复用验收 / 2026-09-09

需求与参考：`03_design/STUDIO_BOOKING_PROFILE.md`。删除老客可忽略提示；首次成功提交预约后保存，后续使用资料摘要与修改入口；个人资料与店主顾客后台共用。

## 已完成

- 独立 `studio_booking_profiles` 表按已认证账号 ID 关联，不改变共享账号昵称、头像、登录邮箱或钱包。
- 首次成功提交时原子保存；已保存时确认页显示称呼、联系渠道和联系值。点击修改可编辑，返回/刷新/语言切换保留填写；换浏览器从服务端取得资料。
- 个人资料可单独保存预约资料，即使账号尚未设置昵称也不会被强制要求另填昵称。管理员列表显示并可搜索，详情可修改。
- 已有有效历史预约按本人账号回填；显式清空后不被历史复活。旧版没带资料版本号的预约能创建初始资料，但不会覆盖已有资料。原预约快照保持不变。
- 版本冲突保留输入，提供使用最新资料的入口。提交时使用用户已核对的资料版本，不在点击提交后静默替换成其他窗口刚修改的信息。
- 请求丢失后的重试沿用原编号，资料和预约均不重复。账号切换清除原账号联系草稿，未确定结果的请求仍绑定所属账号。
- 移除 `visit-flow.returning_help`，新增 `booking-profile` 中英功能文字。65 个文案模块获本轮功能授权，字体已覆盖新增中文字符；未改品牌图像与经营文案。
