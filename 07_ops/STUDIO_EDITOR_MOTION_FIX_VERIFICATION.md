# 轮播、营业时间与文字预览修正

2026-09-09 UTC（店主所在 Toronto 为 09-08）。来源：两台 Windows Chrome 轮播效果不同、全天介绍显示18:00、以及“文字改了，右侧预览没有变化”。本轮没有更换宣传文案；完整结束时间模板和必要的操作反馈已经按该要求记入文案变更档。

## 已核实的原因与边界

- 原轮播依赖浏览器原生 smooth scroll，并读取本站动效偏好。本站未覆盖时，Windows 的 reduce 会跳过滑动；Chrome 的原生平滑滚动设置也会影响表现。本机原生 Chromium 确实报告 reduce。不能由两张截图断定店主正在使用的另一个标签究竟命中了哪种设置。
- 原全天文案是“前半句 + 代码动态时间 + 单独句号”。动态时间取保存的预约日期，即使当前只是按时体验，也会带入周四18:00。后台编辑前半句无法编辑那段代码生成的时间。
- 公网 `www` 的 `/manage` 留在原域名，首页和详情则跳转到不带 `www` 的域名；原预览在这些页面跨域后，严格同域的 postMessage 被忽略。当前同域版本的文本输入可以复现正常更新，但旧预览没有送达确认、超时状态和重连，所以无法区分断连、旧构建和只在条件状态出现的文字。
- 只读查库：到店页 `pages-Visit` 无成功保存历史（version1、draft/published均空）。因此没有把店主反馈误称为某次服务端保存被拒。最新日志中有其他模块成功发布和排班更新。

## 实现

1. `StudioCarousel.vue` 使用820ms的受控 GSAP 滑动，保留触控滚动与 snap，快速点击从当前帧重新定向，窗口变宽时对齐目标图。目标及相邻图片提前加载，已加载图片保留。
2. 菜单新增“页面动效”：跟随系统／完整动效／减少动效。CSS和JS仍共用 `motion-preference.ts`。菜单的最新选择移除旧诊断链接的 motion 参数并保存在本浏览器；不修改系统设置。
3. 全天说明成为稳定键下的完整双语模板 `{v0}`。未选全天时，按服务端最新正常周排班的最晚营业时间展示；选定有效全天日期后，显示当天结束时间和日期说明。后台最新排班仍决定可约时间，未改写营业数据。
4. 生产预览从同域 `/studio-api/site` 获取HTML，只允许切换至已列出的公开页面路径。父子窗口验证 origin/source，使用递增编号确认内容应用；4秒未确认显示断线并提供重连。旧构建有提示。
5. 预览使用独立的预约状态，不读写顾客草稿。编辑器暂存未保存文字到同标签 sessionStorage；版本冲突继续由服务端409拒绝。保存失败保留输入，重连只刷新预览。
