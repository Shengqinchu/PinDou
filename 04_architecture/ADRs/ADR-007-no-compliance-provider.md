# ADR-007: 不预订国产合规 Provider 应急切换

- **状态**: Accepted（用户在 push back 两轮后明确决策）
- **日期**: 2026-05-24
- **决策者**: 用户
- **影响范围**: ADR-005 / ADR-005a / FUTURE_WORK / Phase 3 提审节奏

## 背景
Phase 0 任务 F 合规调研结论：
- 使用未备案境外大模型（反代 OpenAI gpt-image-2）提供 C 端 AIGC 生成服务，违反《生成式 AI 暂行办法》
- 用户上传人像经反代到 OpenAI 美国服务器，构成跨境敏感个人信息传输（《个保法》第 28 / 38 条）
- 监管查处 / 竞品举报 / 微信抽查概率随用户量上升

Claude Code 提议三种应对：
- A: 最小成本预案（10 分钟注册账号 + 留 key + 留 ADR-007 占位，应急切换能力就位）
- B: Phase 2 顺手接通国产 fallback（半天工作量）
- **C: 不做预案，接受风险**

## 决策（用户原话留痕）

> 用户 2026-05-24 决定 PinDou 上线 + 长期运营只用反代 OpenAI，不预订国产 provider 应急切换。已知风险：被举报 / 抽查 / 备案查处概率随用户量上升，预估月活 1 万后概率 30-50%。接受此风险作为成本换效率的取舍。

## 已知风险（由用户接受）

| 触发场景 | 后果 |
|---------|------|
| 微信小程序提审时审核员抓后端流量 | 拒审（境外模型 + 未备案） |
| 用户量 ≥ 1 万 后竞品举报 | 限期整改 / 下架 |
| 用户量 ≥ 10 万 后监管主动注意 | 下架 + 罚款 + 备案警告 |
| 反代依赖的 Mac Mini + Cloudflare Tunnel 故障 | 服务中断（无 fallback provider，只能走"普通量化"降级） |

## 风险量化（用户决策时已知）

| 月活区间 | 监管主动 | 竞品举报 | 微信抽查 |
|---------|---------|---------|---------|
| < 1K | ~0% | ~0% | 仅提审一次 |
| 1K - 1 万 | ~1% | 5-15% | 偶尔 |
| 1 万 - 10 万 | ~5% | 30-50% | 较频繁 |
| > 10 万 | ~30% | > 60% | 持续 |

商业目标 6-10K RMB/月 月入意味着需要 1-3 万月活，正落在"举报概率 30-50%"区间。

## 仍然存在的应急能力（不依赖本 ADR）

Codex 已在 task_C 实现 `StylizationProvider` 抽象层。**架构层面**接入新 provider 不超过半天工作量。只是没有"预订"——出事时从注册账号到上线切换的窗口约 1-2 天。

本 ADR 拒绝的是"提前注册账号 / 提前接通"，不是"永远不接"。

## 强制监控触发条件（Claude Code 必须主动提醒）

发生以下任一情况，Claude Code 在下一次对话开始时**立刻顶上来**提醒用户重启合规决策评估：

- [ ] PinDou 月活 ≥ 1 万
- [ ] 小红书 / 微信 / 网信办收到任何关于 PinDou 的违规投诉 / 举报
- [ ] 微信小程序审核被拒（不论原因）
- [ ] 反代服务故障超过 6 小时
- [ ] 法律法规 / 平台规则关于境外大模型 / AIGC 的口径变化

## 后果

### 正面
- 研发期 + 上线期零额外成本
- 不分散 Codex Phase 2 工时

### 负面
- 上述风险全部由项目承担
- 出事后从应急切换到恢复服务的窗口期 1-2 天（用户体验中断）
