# ADR-011: 虎皮椒微信支付码方案（支付码而非 H5 跳转）

- **状态**: Accepted
- **日期**: 2026-05-25
- **决策者**: 用户 + Claude Code（PM 角度二次评估）
- **影响范围**: 变现路径自动化、客服工作量、后端 webhook 接收、PRD §4.8 修订

## 背景

ADR-006 个人主体小程序不能开通官方微信支付。

ADR-003 修订版采用"加客服扫码付"作为支付方案：
- ✅ 优点：合规、零成本
- ❌ 缺点：客服 24/7 守、用户加好友体验断裂、扩量后人工 bottleneck

用户在月入未达 1500 触发个体工商户升级前，希望**自动化支付**。

## 决策

采用**虎皮椒支付码方案**（不是 H5 跳转方案）：

### 用户路径
```
1. 用户在小程序 paywall 选月卡 28 元
2. 前端调 POST /api/v1/payment/order/create
3. 后端调虎皮椒 API 生成支付订单 → 返回订单号 + 支付二维码 URL
4. 小程序内显示二维码（取代之前的"客服微信二维码"）+ 文案"长按识别付款"
5. 用户长按二维码 → 微信识别 → 自动拉起微信支付 → 输密码完成
6. 虎皮椒 webhook 通知后端订单状态 = paid
7. 后端开通用户额度（写 user.paid_credits / monthly_card_expires_at）
8. 小程序前端 polling /api/v1/payment/order/{order_no} → 检测到 paid 自动关闭 paywall 跳结果页
```

### 为什么不走 H5 跳转
- H5 跳转需独立 H5 域名 + ICP 备案 + 跨域跳转回小程序（用户可能不回来）
- 支付码方案**不离开小程序**，体验接近原生
- 实现工作量小（接虎皮椒 webhook + 前端轮询订单状态）

## 实现要点

### 后端
- 配置：`HUPIJIAO_APP_ID` / `HUPIJIAO_APP_SECRET` / `HUPIJIAO_WEBHOOK_SECRET`（写 .env）
- 接口：`pindou/services/hupijiao_service.py` 封装下单 / 查单
- 路由：
  - 修改 `POST /api/v1/payment/order/create` → 调虎皮椒 + 返回 `qr_code_url` + `order_no`
  - 新增 `POST /api/v1/webhook/hupijiao` 接收虎皮椒回调（验证签名）
- 订单状态机扩展：`pending_qr → paid_via_hupijiao → credits_granted`
- 防重复回调：webhook idempotency 检查（order_no + status 已是 paid 则忽略）

### 前端
- `Paywall.vue` 改造：
  - 选月卡后调创建订单 API → 拿到二维码 URL
  - 显示二维码 + 订单号 + "长按识别付款"提示
  - 启动 polling（每 3 秒查订单状态，最多 5 分钟超时）
  - 检测到 paid → 关闭 sheet + toast"支付成功"+ 跳作品集页
- 文案改：原"加客服微信扫码付" → "微信扫码付款（虎皮椒）"
- "我有 CDK 兑换码"入口保留

### 安全
- 虎皮椒回调签名验证（用 `HUPIJIAO_WEBHOOK_SECRET` 校验 HMAC）
- 订单金额服务端校验（前端传 sku，金额从后端配置查 → 防篡改）
- 防重放：webhook 同一 order_no 只能从 pending 状态机进 paid 一次

### 兼容现有"加客服扫码"
保留客服扫码作为兜底方案：
- 虎皮椒主路径
- 虎皮椒接口故障 fallback → 客服扫码
- Paywall 加切换："换种付款方式"小按钮

## 理由

- 自动化变现是 ADR-003 商业目标的关键支撑（客服人工不可扩量）
- 支付码方案在小程序场景比 H5 跳转更适用（不离开应用 + 体验近原生）
- 工作量可控（2-3 天 vs H5 跳转的 5-7 天）
- 与现有 paywall UI 几乎兼容（只换二维码内容）

## 后果

### 正面
- 客服 24/7 守解放（订单自动化）
- 转化率提升（流程比加客服扫码短）
- 不依赖 H5 域名备案（绕过个人主体不能官方微信支付的限制）

### 负面
- 虎皮椒抽成（一般 0.6%-2%）+ 提现费（提现到银行卡有费率）
- 虎皮椒平台风险（账号被封 / 服务中断）
- webhook 安全负担（签名 / 防重复 / 防伪造）

### 风险
- 虎皮椒在 2024-2025 年是否仍正常运营？需用户确认账号可用
- 长按二维码识别在不同微信版本表现可能略差（特别旧版本）
- 监管对第三方支付聚合的态度变化

## 备选方案

- **H5 跳转方案**：被否，工作量大 + 体验割裂
- **加客服扫码（ADR-003 当前）**：保留作为兜底
- **官方微信支付（ADR-006 升级触发 C 方案）**：长期最优，月入 1500 后启动

## 后续触发

- 月入 ≥ 1500 → 触发 FUTURE_WORK #6 → 升级个体工商户 + 官方微信支付 → **虎皮椒降级为备份**
- 虎皮椒抽成 + 提现费超过个体工商户成本时：直接走 C 方案

## 关联
- ADR-003（修订）：变现路径加虎皮椒主路线
- ADR-006：个人主体限制依然成立，虎皮椒是绕过方案
- FUTURE_WORK #6：长期升级路径不变
- PRD §4.8：付费方式表更新

## 待用户提供

- 虎皮椒后台配置 webhook URL（指向 https://api.pindou.cn/api/v1/webhook/hupijiao，部署上线后启用，开发期用 ngrok / 本地测试用 mock）
- 虎皮椒商户号注册的主体信息（个人还是个体户？需确认虎皮椒是否支持个人主体）
