# ADR-002: 色卡 / 豆系支持 — 全面信息库 + 产品默认收敛

- **状态**: Accepted（2026-05-24 修订）
- **日期**: 2026-05-24（首版）/ 2026-05-24（修订）
- **决策者**: 用户 + Claude Code
- **影响范围**: 量化算法、材料清单、定价、采购引导、Phase 1 任务范围
- **修订记录**: 取代首版 "MARD + COCO 双色卡 + Phase 1 不做自有色卡" 的收敛思路；现在分两层处理

## 背景
首版决策只支持 MARD + COCO。但用户私有素材测试 + 拼豆领域调研（`01_research/tech/perler_bead_domain_notes.md`）显示：
- 不同豆径（2.6mm Mini / 5mm Midi / 10mm Maxi）影响成品尺寸、定价、可拼性
- 多品牌（MARD / COCO / Hama / Perler / Artkal / 国产其他）在不同用户群体里都有需求
- 收敛产品功能不等于收敛数据底层；底层信息库越全，未来切品牌的成本越低

## 决策（双层）

### 数据层：信息库尽量全
- **品牌**：MARD / COCO / Hama / Perler / Artkal / 国产其他主流（任务 H 完整调研）
- **豆径**：2.6mm Mini / 5mm Midi / 10mm Maxi
- **每品牌 × 豆径** 都要有完整字段：色号、官方 HEX、市场价、电商渠道、跨品牌 CIEDE2000 近邻
- **数据结构**：`01_research/colormap/<brand>_<size>.json`，schema 统一，后端可直接消费
- **信息库由 Codex Task H 完成，作为 Phase 1 启动前的数据基线**

### 产品层：默认收敛
- **Phase 1 MVP 默认开启**：**MARD 5mm 中豆**（认知度最高、供应最稳）
- **Phase 1 隐藏可切换**：UI 不暴露但配置可切，便于内测验证
- **Phase 2+ 产品功能**：UI 暴露品牌 / 豆径选择 + 跨品牌图纸转换 + 跨豆径图纸切换
- 跨品牌可替代对照表（CIEDE2000 近邻）信息库就绪即可用，UI 露不露看节奏

## 理由
- 数据全 = 商业灵活性（未来用户问"我手头是 XX 牌"立刻能接，不用补调研）
- 产品收敛 = 减少 Phase 1 测试矩阵 + 减少用户决策疲劳
- Phase 0 Task D 已完成 MARD + COCO，是 Task H 的起点

## 后果

### 正面
- Phase 1 启动时所有底层数据就绪，Phase 2+ 扩品牌只需开 UI
- 跨品牌 / 跨豆径切换是天然差异化卖点（竞品都是单品牌单规格）
- 不依赖二手 / 不准的色卡表

### 负面
- 信息库维护成本高（多品牌价格波动、停产、新色追加）
- Codex Task H 工时增加（预估 3-4 天）

### 风险
- 品牌方商标边界：任务 F 合规报告确认"可作兼容描述使用，不得暗示官方授权"——任务 H 的产出文档需避免品牌 Logo / 不能写"XX 官方色卡"

## 备选方案
- **单 MARD 单豆径**：被否，信息库不能复用、扩品牌成本高
- **全品牌 Phase 1 全开**：被否，产品测试矩阵爆炸、用户决策疲劳
