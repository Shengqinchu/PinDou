# ADR-005a: 写实人像 GPU 决策延后到 PoC 数据驱动

- **状态**: Accepted
- **日期**: 2026-05-24
- **决策者**: 用户 + Claude Code
- **影响范围**: ADR-005 写实人像主路线、Phase 0 任务 C 验收标准
- **修订关系**: Amends ADR-005（不替代，仅修订写实人像路线启动条件）

## 背景
ADR-005 原本将写实人像主路线定为 SD + IPAdapter(Face) + ControlNet(Depth)，依赖本地/云 GPU。

用户在 2026-05-24 review 时质疑该路线必要性：
1. GPU 路线在**原图分辨率**上 ID 保持更强（学术 benchmark 领先 15-30%）；
2. 但拼豆最终输出是 ~100×100 像素 × 24 色量化图，**量化会糊掉 GPU 的精度优势**；
3. 量化后真正影响"像不像"的是脸型轮廓、肤色色块大小、五官相对位置——API 路线（gpt-image-2、即梦、通义万相）完全能做好这些粗粒度特征。

## 决策
- **Phase 0 / Phase 1 全部走纯 API 路线**，不引入 GPU。
- 写实人像、Q 版、宠物、通用卡通四个风格预设统一通过反代 API（主：`gpt.xiaochisaascn.org/v1` 的 `gpt-image-2`；备：火山即梦 / 阿里通义万相，待 API 补齐后接入）。
- **PoC 验收标准强制变更**：写实人像 ID 保持率测试**必须用量化输出图**，不用 AI 生成的原图。
- **GPU 决策时机后移**到 PoC 验收数据。

## PoC 量化输出 ID 保持率验收方法（强制）
1. 准备 5 张人像 + 5 张情侣合影测试图，每张过：原图 → AI 风格化 → 量化输出图（按 MARD 色卡量化到 100×100）
2. 招募 5 位无关志愿者主观投票"量化输出图像不像本人"，每张图独立打分（1-5 分，5 = 非常像）
3. 计算**平均分**和**"≥3 分"通过率**

### 验收门槛
- 平均分 ≥ 3.0：API 路线达标，永久放弃 GPU，关闭 ADR-005a，更新 ADR-005 主表
- 平均分 2.0–2.9：边界，组合调优（换 prompt / 换 provider / 加抖动）后复测
- 平均分 < 2.0：API 路线不达标，**触发 FUTURE_WORK.md 第 1 条**，写实人像引入 GPU 路线（AutoDL 按小时租 4090）

## 后果
- 正面：MVP 期省 GPU 成本（按小时租 4090 约 10-15 元/小时，开发期可省千元级），架构简化
- 负面：若 PoC 验收不达标，需在 Phase 2/3 临时补 GPU 路线，工期会有冲击
- 风险已留痕：FUTURE_WORK.md 第 1 条 + 本 ADR 验收门槛
