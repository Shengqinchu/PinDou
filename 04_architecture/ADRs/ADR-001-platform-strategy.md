# ADR-001: 平台策略 — 小程序优先 + Web 预埋

- **状态**: Accepted
- **日期**: 2026-05-24
- **决策者**: 用户 + chat 端 Claude
- **影响范围**: 全局架构、Phase 1 起所有端

## 背景
拼豆图纸用户主要在移动端使用（拍照 → 生成 → 看材料清单 → 下单），但同时也存在 PC 端用户上传高清原图的场景。早期资源有限，无法同时把两端 UI 都做完。

## 决策
- **微信小程序优先**：MVP 完整功能在小程序落地。
- **Web 端预埋**：Phase 1 完成路由、数据模型、API 抽象层的 Web 端骨架，UI 完整度延后。
- **PMF 后再补 Web UI**：等小程序跑出付费转化数据后，再投入 Web 端 UI 工时。

## 理由
- 拼豆用户重度集中在小红书 + 微信生态，分享链路天然走小程序。
- 移动端拍照即传体验最短。
- 后端如果一开始就按"端无关"设计，后期补 Web UI 成本可控。
- 提前预埋路由 / 数据模型避免后期重构。

## 后果
- 正面：聚焦资源、加速 MVP 上线。
- 负面：Web 用户早期体验受限，PC 高清场景被动等待。
- 风险：若小程序审核反复（AIGC 类目敏感），会延迟整个产品上线；缓解策略见 ADR-005 fallback chain 与合规预案（任务 F）。

## 备选方案
- **Web 优先**：被否，移动端是拼豆主场景，且无 SEO 资产储备。
- **双端并行**：被否，资源不足，会两边都做不到位。
