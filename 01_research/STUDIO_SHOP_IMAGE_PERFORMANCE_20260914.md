# 拼豆小店图片加载评估

后续实现已测试部署，当前结果见 [图片与动效验收](../07_ops/STUDIO_IMAGE_MOTION_VERIFICATION_20260914.md)。下文保留本轮实现前的测量。

店主问题：首次进入商品分类要等待图片，后续切换有缓存；是否能替顾客提前加载，以及是否值得实现。

结论：值得做列表缩略图与有限的后台预加载。顾客不需要手动点遍分类；浏览当前页面时可以提前准备下一组可能查看的图片。首次传输仍需发生，不能在顾客尚未访问网站时将缓存预先放入其手机。此次只读诊断和本地实验完成，未修改生产代码、图片、商品或服务器设置。

## 当前线上证据

- 核验版本 `20260914013422-studio-v7`。242 个公开商品，240 张不重复封面合计 20,331,107 字节，约 20.3 MB；B 系列 33 个商品，封面合计 2,844,194 字节。
- 当前列表与商品详情共用原图。B 系列单色图为 800 × 800，桌面列表实测显示宽约 224 CSS 像素；B1 文件 85,836 字节，B2 为 85,104 字节。源图本身已是 WebP，仍有按显示尺寸提供小图的空间。
- 公开媒体响应为 `Cache-Control: public, max-age=31536000, immutable`，图片 URL 使用内容哈希。复用缓存与上传新图片更换 URL 的机制已存在。
- 本轮 Chromium 首次切到 B 系列到首屏 8 张图片解码完成约 3,512 ms；返回同分类 56 ms，B 图片传输量为 0。首次资源响应记录为 Cloudflare `MISS`。
- 随后的独立 WebKit 上下文首次切换 378 ms、返回 151 ms，返回传输量仍为 0；资源为 Cloudflare `HIT`。这同时说明浏览器缓存和 CDN 节点缓存都有效，两个引擎的首访时长不能直接作为浏览器性能比较，也不能将该单次时长当所有顾客的平均值。
- Chromium 首屏等待期间已有 33 张 B 系列图完成下载，而实际可见的是 8 张。代码使用原生 `loading="lazy"`，浏览器会提前请求视口附近的图片，并非严格只下载当前看见的图片。
- 当前已有导航页面代码的意图预取，`route-loaders.ts` 在悬停/键盘聚焦时预取相应页面模块；商品分类图片尚无独立的、有预算的预加载队列。

## 本地实验

### 预览图体积

对现存 B1–B32 原始 WebP 逐张校验其哈希与当前线上地址一致，再用 Sharp 在内存中计算 WebP quality 85 的派生图体积；源文件未修改，派生图未上传。

| 宽度 | 32 张合计字节 | 比原图减少 |
|---|---:|---:|
| 800 px 原图 | 2,712,758 | — |
| 640 px | 1,704,888 | 37.2% |
| 480 px | 1,219,754 | 55.0% |
| 320 px | 709,632 | 73.8% |

此项是体积实验，不是无损质量承诺。实施时需要针对色号文字、颜色和高密度屏幕检查清晰度，列表使用 320/480/640 的响应式选择，详情继续使用原图。

### 提前加载对点击等待的影响

Chromium 新浏览器上下文，使用 CDP 模拟 8 Mbps 下行、150 ms 附加网络延迟。先完成 A 系列当前图片加载，然后分别测试默认切换，以及先低优先级、并发 2 张预读 B 系列首屏 8 张图再切换。

| 条件 | 点击前后台准备耗时 | 点击到首屏图片可见 |
|---|---:|---:|
| 原行为 | 0 | 1,991 ms |
| 首屏 8 张图预读完成 | 2,497 ms | 61 ms |

这证明能把部分等待移到顾客浏览当前页的时间段；没有消除网络传输。用户在后台准备完成前立即切换，仍可能等待。本试验为单组网络模拟，不代表真实加拿大所有网络，CDN节点已被先前诊断请求热身。

## 建议实施范围与顺序

1. **列表预览图优先**：原图保留，派生预览图使用包含源哈希和尺寸的稳定地址；已有商品一次性生成，以后后台上传时自动生成。前台 `srcset` / `sizes` 按实际宽度和屏幕密度选择，详情继续加载原图。
2. **首屏优先**：可见首屏图片及时请求，其余图片延迟；避免给所有图片同时设置高优先级。保持商品布局稳定并设置明确尺寸。
3. **有限后台预加载**：当前首屏完成且浏览器空闲后，低优先级预读相邻分类首屏 4–8 张图；鼠标停留/键盘聚焦分类时补充意图预读。建议最多并发 2 张、每轮约 0.5 MB，来源变化或用户离开时停止无关预读，省流模式/慢网跳过。具体预算以缩略图实际体积及测量调整。
4. **缓存保留并正确更新**：继续复用内容哈希和长期缓存。店主换图片即更换派生 URL，不能用不变的地址配永久缓存导致顾客看到旧图。

不建议把全部约 20.3 MB 商品封面一次性预读。顾客通常只查看少数分类，全部预读会消耗流量，并与当前可见内容竞争网络资源。CDN 已有缓存，此次无需仅为此问题增加新的 CDN 服务或提高服务器配置。

正式实施的验收应包含：新上下文冷缓存、暖缓存、立即切换与停留后切换、320/390/1440 px、高像素密度、限速与省流模式、后台换图不显示旧缓存；保留三张风景商品原图及所有系列组合原图资料。
