# V4：可编辑性、比例和小互动

执行清单：`02_product/STUDIO_VISION4_PROGRESS.md`。采用项目 pindou-studio-design 规范、PDF 逐页读取和 GSAP 技能关于变换层、时间线、销毁和可中断动画的实现方法。

## 模块边界

- Vue SFC 模板描述每个页面／组件；JSON 内容模块提供中英文固定文字。`editor.ts` 管理草稿、版本、图片上传和全站文字查找；`content-store.ts` 管理公开覆盖与预览；`commerce.ts` 统一网络错误和请求编号。
- `MediaUpload.vue` 提供所有编辑器共用的真实文件选择按钮；`EditorDiagnostics.vue` 查询运行状态；`editor.css` 只控制编辑器布局。避免借用表单说明的负外边距。
- `BeadingProcess.vue` 提供五步图文，`process.css` 控制排版，`components-BeadingProcess.json` 提供可编辑的内容，`media-assets.json` 提供可替换的图片。
- `motif.ts` 管理装饰动画，`BrandMotif.vue` 保留店主原图裁切，三个嵌套层分别负责布局、漂浮和捏捏。慢漂浮 8.4–9.6 秒往返，悬停转动约 0.85 秒，捏捏 0.22 秒压缩后 1.1 秒弹性回弹。离屏、后台标签和减少动态偏好下停止。
- `clipboard.ts` 是浏览器兼容层，`CopyContact.vue` 是共享展示与反馈组件；Clipboard API 被微信 WebView 拒绝时尝试原生复制，再提供可选文字。
- 后端 `content.py` 管理有版本的内容和图像，`xhs_import.py` 只负责受限的源站读取，`observability.py` 管理脱敏请求日志与诊断。无需机械拆分 Vue 成独立 HTML 文件；功能边界和职责已经独立。

## 布局约束

桌面内容宽度由 1424 收紧到 1280，主要标题约原 90%，首页大图最大宽度从 1136 收到 795。字号、图片、留白各自连续适配，不使用整页 `zoom` 或 `transform:scale`。短屏进一步收紧首屏留白和图高；长图文仍可自然滚动，不能为了填进一屏而裁掉内容。

手机遵循单列、16px 表单输入、至少 44px 主要触控区和安全区；200% 浏览器缩放按照变窄后的布局重排。预览 iframe 的缩放仅限后台的设备预览，不影响真实网站字号和命中区域。

## 编辑与故障恢复

网站“发布此页”把保存与发布放进一个数据库事务；任何一步失败均回滚。图片上传只更新当前草稿，并在对应图片旁说明还需发布。保留内容版本冲突保护，不静默覆盖其他窗口的修改。全站找文字可直接定位标题所在模块，避免误选“日记正文页”。

上传格式依据文件实际解码而非文件名；JPEG/PNG/WebP 支持原图，网站替换另支持 AVIF/BMP 转 WebP。HEIC/HEIF 明确提示先导出 JPG。记录请求编号、状态、耗时及错误代码，排除 URL 查询参数、图片字节、内容正文、姓名、联系方式和登录凭据。诊断嵌入编辑页面；截图中 7 个停用的旧交易导航注释隐藏。

## 小红书研究

已核对 [xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 和 [DeliciousBuding/xiaohongshu-skill](https://github.com/DeliciousBuding/xiaohongshu-skill) 的项目文档。两者能用网页登录会话读取帖子，均不能凭 skill 消除登录／有效分享链接的要求；本任务只需要读取，不需要发布、评论、点赞或收藏功能。

2026-09-08 本机实测：店主公开主页返回 31 条标题预览，但 `id` 和 `noteCard.noteId` 均为空；旧合集公开页只返回前 10 条较早内容。现有线上 7 篇完整帖子最新为 7 月 31 日。新稿完整性需要逐篇取得有效分享页或登录后读取，不用标题预览替代全文。导入问题和后续结果记入 V4 验收记录。

后台导入现为持久化任务：独立 worker 读取原帖和原图，返回排队／读取／进度／完成或失败，前端保存任务编号并在刷新后继续查看。图片下载完成顺序可以不同，保存图序仍与原帖一致。部署中断明确记录失败，重复导入不覆盖原有草稿。

前端运行错误仅上报错误类别、应用脚本文件名、行号和归一化页面名；每页去重最多 5 条，服务端每小时限额且总记录最多 2000 条。不发送错误消息、堆栈、页面文案、查询参数、用户 ID 或登录凭据。未接入外部告警渠道。
