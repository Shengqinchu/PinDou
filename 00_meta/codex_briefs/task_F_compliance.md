# Task F — 合规调研

**Status**: pending
**Owner**: Codex

## 背景
合规是上线 blocker。AIGC 类目 + 人像上传 + 小红书引流，每一项都有红线。**ADR-006 确定主体为个人**，这进一步收窄了可选类目和变现方式。

本任务的输出会直接影响：
- 小程序类目选哪个
- 提审前要不要补什么材料
- 跨境数据传输怎么处理（FUTURE_WORK 第 2 条）
- 小红书引流话术能写什么不能写什么

## 目标
输出一份"上线 checklist"，每条都标明：要求 / 个人主体能否满足 / 必须做的事。

---

## 调研维度

### 维度 1：用户人像上传的隐私合规
- 《个人信息保护法》第 28 条对"敏感个人信息"的定义和处理要求
- 用户授权同意书该怎么写（最小必要原则、单独同意）
- 删除权 / 知情权 / 撤回权的产品实现要求
- 「不出境」承诺 vs 跨境传输标准合同备案（**直接关联 FUTURE_WORK 第 2 条**）

### 维度 2：ICP 备案 + 小程序类目
- 个人主体能申请的小程序类目清单（重点：能不能选"工具" / "图像处理" / "AIGC"）
- 类目要求的资质（如：是否要前置审批文件）
- 域名 ICP 备案（个人备案流程 + 时长 + 限制）
- AIGC 类目 vs 工具类目的审核差异

### 维度 3：AIGC 内容审核 + 算法备案
- 《生成式人工智能服务管理暂行办法》对个人主体的具体要求
- 个人主体能不能做 AIGC 服务（**关键问题**）
- 算法备案流程（境内 vs 境外模型差异）
- 内容审核要求（用户上传图过滤 + 生成图过滤 + 文案过滤）

### 维度 4：商标边界
- "MARD" / "COCO" / "佩拉宝" 等色卡品牌名能否在商品描述中使用
- 在小程序内提供"对照表"是否构成商标使用
- 在小红书引流文案中提到品牌名的边界

### 维度 5：小程序提审常见拒审原因
- AI 类小程序的常见拒审点（话术、未明示 AI 生成、未提供用户协议、未做内容审核）
- 类目误用拒审
- 个人主体的额外限制

### 维度 6：小红书 / 微信生态引流合规
- 小红书 ToS 中关于"导流到外部产品"的红线
- 微信生态的"外链 / 引流"限制
- 哪些话术触发限流 / 封号（参考行业案例）
