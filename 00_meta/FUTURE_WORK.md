## 2. 用户上传图片的跨境合规
- **当前决策（2026-05-27 ADR-012 更新）**：MVP 期改用微信云托管 + 云托管 MySQL + 腾讯云 COS，用户上传图片不再依赖日本服务器或自建上海机本地盘
- **已缓解风险**：用户原图与作品文件的生产持久化迁回微信云托管 / COS 国内链路，原“日本服务器本地存图”风险关闭
- **剩余风险**：AI 精品路径仍会调用 `gpt.xiaochisaascn.org` 反代到境外模型，用户原图可能进入反代处理链路；这仍按 ADR-007 作为用户已接受风险管理
- **触发条件 = 必须回头处理**：
  - 小程序提审前（Phase 3）— 否则可能直接被拒
  - 或：用户量达 ~1000 后任何一次合规投诉
  - 或：日方 / 中方监管政策变化
- **回头要做**：
  - 提审前重新审查隐私政策中“AI 处理链路 / 反代模型”的披露口径
  - 评估国产合规图像 provider 作为 AI 精品路径主路线或备份
  - 评估“用户原图不传 AI，只做本地脚本图纸”的无跨境降级路径
- **预计阶段**：Phase 2 末 / Phase 3 初
- **风险等级**：高（直接影响上线）
- **记录日期**：2026-05-24

## 3. 服务器硬盘扩容 / 对象存储迁移
- **当前决策（2026-05-27 ADR-012 更新）**：MVP 期改用微信云托管 + 腾讯云 COS，已通过存储抽象支持 `STORAGE_BACKEND=cos`，原“上海机本地硬盘扩容”路径降级为 legacy fallback。
- **状态**：✅ 已通过云托管 + COS 解决 MVP 期容量风险；继续监控 COS 成本与读写失败率。

  - 或：图片访问 P95 延迟 > 2 秒
  - 或：云托管 / COS 限流影响上传、生成或作品集访问
- **回头要做**：
  - 评估 COS CDN / 防盗链 / 图片缩略图策略

- **预估到达时间**：PMF 前概率低；用户量 > 5 万后按 ADR-012 重新核算
- **预计阶段**：Phase 4 PMF 期
- **风险等级**：中高（PMF 期可能要紧急处理，建议提前 1 个月预备）
- **Claude Code 监控职责**：deployment.md §9 监控中 COS 成本 / 读写失败率异常 → 立刻顶上来提醒

## 13. 管理员后台安全加固（后台标准 §2 风险记录）
- **背景**：管理员后台 Batch 1（commit e22c2d3）按 saas-playbook 后台标准实现，两处 Day 0 可接受但需回头加固：
- **13a 登录限频内存态**：失败限频用进程内 `_LOGIN_FAILURES` dict，云托管多实例（max 5）+ 冷启动（min 0）下不共享、重启即清。单 admin + 强随机密码可接受，被刷再升级。与 [#9 CDK 频控] 同类，建议一起搬到 Redis/DB。
- **13b 后台 token 用 localStorage（标准 §2 兼容原因记录）**：标准要求优先 HttpOnly+Secure Cookie；PinDou 后台沿用小程序同款 JWT + localStorage，是为复用现有 `/admin/login` 鉴权、单文件 admin.html 零额外依赖。**风险**：XSS 可读取 token。**缓解**：后台是独立单页、不嵌第三方脚本、admin 账号唯一。**触发升级**：后台引入任何第三方 JS / 多管理员 / 上公网入口前，改 HttpOnly Cookie。
- **触发条件**：[ ] 加 operator/viewer 实际账号　[ ] 后台入口暴露到非自用范围　[ ] 第一次安全事件
- **风险等级**：中
- **记录日期**：2026-05-30

## 14. 原生 App（iOS/安卓）—— 上线拿到用户之后再说
- **当前决策**：不做。一个付费用户都没有、web/小程序未正式上线前做 App 是本末倒置，且 App 是所有平台 ROI 最差的。
- **关键事实**：
  - App 只是客户端，调现成的云托管后端 API，**不需要新服务器，更不需要移动云**（移动云备不了案/运维重/9-25 到期，结论同正文）。
  - uni-app 能 `uni build -p app` 从**同一套代码**编安卓/iOS，**不用重写**。
  - 真正卡 App 的是：Apple 开发者号、App Store 审核要软著(+可能 ICP)、**内购抽 30% 会废掉虎皮椒**、安卓要上应用宝/华为/小米/OPPO/vivo 多商店各自备案。
- **触发条件**：[ ] web/小程序已上线且有稳定付费用户　[ ] 有明确"App 才能满足"的需求（如推送/离线）
- **记录日期**：2026-06-01

## 15. Web 上传公开化 + 生成时鉴权
- **当前决策**：`/upload` 对未登录用户开放，允许先上传照片和配置参数；真正消耗额度/创建作品的"确认生成"动作再要求登录或注册。
- **实现形态**：登录/注册抽为可复用 `AuthPanel`，上传页使用内联弹窗，避免整页跳 `/login` 导致 `selectedFile` 这类浏览器内存态丢失；`/login` 页面继续复用同一组件。
- **仍需保护的路由**：`/loading`、`/result/:id`、`/editor/:id`、`/works` 继续走路由守卫，防止未登录访问用户作品和生成结果。
- **触发复盘**：[ ] 未登录上传转化率低　[ ] 登录弹窗导致验证码/注册投诉　[ ] 需要接入第三方登录或游客临时作品。
- **风险等级**：中（产品漏斗更顺，但鉴权边界前移，需要守住生成动作）
- **记录日期**：2026-06-06
