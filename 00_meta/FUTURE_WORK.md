## 1. 写实人像作为 Phase 2+ 可选功能（ADR-005a 修订后降级）
- **当前决策**：Phase 1 主路线确定为 Q 版 FinishedPreview，写实人像降为 Phase 2+ 可选功能（"忠于原貌"模式）。GPU 决策路径在 ADR-005a 修订中关闭。
- **触发条件 = 重新评估**：
  - Phase 2+ 用户反复要求"做得像本人"成为 top 1 需求
  - 或：竞品上线类似"写实拼豆"功能且转化率高
  - 或：长辈纪念照 / 婚纱拼豆等特殊场景出现批量订单
- **回头要做**：重新评估技术路径（届时国内 GPU / 云 ComfyUI / API 演进版本都会变化，不预判方案）
- **预计阶段**：Phase 2+ 数据驱动
- **风险等级**：低（Phase 1 主路线 Q 版 + FinishedPreview 不依赖此项）
- **记录日期**：2026-05-24（修订）

## 2. 用户上传图片的跨境合规
- **当前决策（2026-05-27 ADR-012 更新）**：MVP 期改用微信云托管 + 云托管 MySQL + 腾讯云 COS，用户上传图片不再依赖日本服务器或自建上海机本地盘
- **已缓解风险**：用户原图与作品文件的生产持久化迁回微信云托管 / COS 国内链路，原“日本服务器本地存图”风险关闭
- **剩余风险**：AI 精品路径仍会调用 `gpt.xiaochisaascn.org` 反代到境外模型，用户原图可能进入反代处理链路；这仍按 ADR-007 作为用户已接受风险管理
- **触发条件 = 必须回头处理**：
  - 小程序提审前（Phase 3）— 否则可能直接被拒
  - 或：用户量达 ~1000 后任何一次合规投诉
  - 或：日方 / 中方监管政策变化
- **回头要做**：
  - 提审前重新审查隐私政策中“AI 处理链路 / 反代模型”的披露口径
  - 评估国产合规图像 provider 作为 AI 精品路径主路线或备份
  - 评估“用户原图不传 AI，只做本地脚本图纸”的无跨境降级路径
- **预计阶段**：Phase 2 末 / Phase 3 初
- **风险等级**：高（直接影响上线）
- **记录日期**：2026-05-24

## 3. 服务器硬盘扩容 / 对象存储迁移
- **当前决策（2026-05-27 ADR-012 更新）**：MVP 期改用微信云托管 + 腾讯云 COS，已通过存储抽象支持 `STORAGE_BACKEND=cos`，原“上海机本地硬盘扩容”路径降级为 legacy fallback。
- **状态**：✅ 已通过云托管 + COS 解决 MVP 期容量风险；继续监控 COS 成本与读写失败率。
- **触发条件 = 必须回头处理**：
  - COS 月成本连续 2 个月超过 200 元，且高于传统服务器 + 对象存储组合
  - 或：图片访问 P95 延迟 > 2 秒
  - 或：云托管 / COS 限流影响上传、生成或作品集访问
- **回头要做**：
  - 评估 COS CDN / 防盗链 / 图片缩略图策略
  - 必要时回退到 `07_ops/deployment_legacy.md` 的传统部署或混合部署
- **预估到达时间**：PMF 前概率低；用户量 > 5 万后按 ADR-012 重新核算
- **预计阶段**：Phase 4 PMF 期
- **风险等级**：中高（PMF 期可能要紧急处理，建议提前 1 个月预备）
- **Claude Code 监控职责**：deployment.md §9 监控中 COS 成本 / 读写失败率异常 → 立刻顶上来提醒

## 4. AIGC 算法备案
- **当前决策**：Phase 0/1 用反代 gpt-image-2 跑 PoC，研发期免备案
- **触发条件 = 必须回头处理**：
  - 小程序提审前（Phase 3）— 类目"AIGC 工具"硬要求
  - 或：用户量达 ~1 万触发监管关注
- **回头要做**：
  - 启动算法备案（如使用境外模型，备案路径更复杂）
  - 或：切到国产合规通道（火山 / 阿里通义）作为主路线，反代作备份
- **预计阶段**：Phase 3 启动前
- **风险等级**：高（不备案不能上线 AIGC 类目）

## 5. Web 端 UI 补齐
- **当前决策**：Phase 1 只做 Web 端路由 + 数据模型骨架，UI 完整度等小程序 PMF 后再补
- **触发条件 = 必须回头处理**：
  - 小程序月活 > 1 万 且付费率 > 3%（PMF 信号）
  - 或：用户反复反馈"想在 PC 上传高清图"

- **预计阶段**：Phase 5
- **风险等级**：低

## 6. 小程序主体升级（ADR-006）
- **当前决策（2026-05-27 ADR-012/ADR-011 更新）**：MVP 阶段仍以个人主体注册；云托管解决部署域名 / 备案前置问题，虎皮椒支付码解决过渡收款，但不等于官方微信支付能力
- **触发条件 = 必须回头处理**：
  - 类目审核被拒且差异点明确指向主体类型
  - 或：月入达到目标下限的 50%（约 3000 RMB/月）
  - 或：用户量 > 1000 且付费需求强烈
  - 或：广告联盟 / 微信支付变现链路被卡死
- **回头要做**：升级到个体工商户（首选）或企业主体；重新走类目申请；可能需要算法备案
- **预计阶段**：Phase 4 末 / Phase 5 初
- **风险等级**：中高（影响多条变现路径）

## 10. 拼豆板 board_profile 多规格支持
- **当前决策**（ADR-010 + quality_review_v2）：MVP 默认 26×26（国内拼豆板规格，单板/双板/三板/四板 = 26/52/78/104）
- **Codex 调研发现**：Hama / Perler / Artkal 等国际品牌偏 **29×29** 大方板（Hama 841 pins / Perler 5.7 inch / Artkal 14.5cm）
- **当前不支持国际板**：所有 26-倍数尺寸预设没考虑 29-倍数
- **触发条件 = 必须升级**：
  - [ ] PinDou 月活 ≥ 5000 且海外用户占比 ≥ 5%
  - [ ] 用户在小红书反馈 "我用的是 Hama 板" 频次 > 月 30 次
  - [ ] 国际品牌色卡 UI 暴露（FUTURE_WORK 第 7 条触发）
- **回头要做**：
  - 设计 `board_profile` schema（含 board_size / unit_mm / pin_count_per_board）
  - SizePreset 与 board_profile 关联，按用户选的 board 动态生成尺寸预设
  - 后端 PatternBuilder.build 加 board_profile 参数
  - 前端选择 board 时尺寸预设联动
- **预计阶段**：Phase 4+
- **风险等级**：低（数据已就绪，国内 MVP 不阻塞）
- **记录日期**：2026-05-25（v2 调优 Codex 调研发现）

## 9. CDK 频控升级（Redis / DB attempt log）
- **当前决策**：CDK 兑换频控用单进程内存 dict 存"用户最近 N 次尝试时间"（task 4 实现）
- **MVP 期 OK**：Phase 2 / 3 单 worker 部署（uvicorn 默认）足够，无并发问题
- **触发条件 = 必须升级**：
  - [ ] uvicorn 配置 `--workers > 1` 之前
  - [ ] 用户量 ≥ 1 万（防滥用攻击概率提升）
  - [ ] 第一次发生 CDK 滥用事件（黑产批量兑换 / 工作室盗号）
- **回头要做**：把内存 dict 换成 Redis 或 DB attempt log 表（user_id + ip + attempted_at + 24h 滑动窗口查询）
- **预计阶段**：Phase 3 末 / Phase 4
- **风险等级**：中（被滥用前没影响，被滥用后影响所有 CDK 用户）
- **记录日期**：2026-05-25（Codex task 4 review 提出）
